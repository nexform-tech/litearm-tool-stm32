# LiteArm STM32 上位机工具 —— 运行说明

这是 **litearm-tool-stm32** 的免安装版本：解压即用，**目标机不需要装 Python，也不需要装任何依赖**。

---

## 一、启动

```bash
tar xzf litearm-tool-stm32-<版本>-linux-x86_64.tar.gz
cd litearm-tool-stm32-<版本>-linux-x86_64
./litearm-tool
```

图形界面里直接双击 `litearm-tool` 也可以（若桌面环境询问，选"运行"）。

**从终端启动更好**：一旦启动出错，错误信息会直接打在终端上；双击启动时出错是没有提示的。

---

## 二、系统要求

| 项 | 要求 |
|---|---|
| 操作系统 | 64 位 Linux |
| glibc | **≥ 2.35**（Ubuntu 22.04 / Debian 12 及以上；`ldd --version` 可查） |
| 串口权限 | 当前用户须在 `dialout` 组 —— 见下 |

> glibc 低于 2.35 会报 `GLIBC_2.xx not found` 且无法启动。本包是在 Ubuntu 22.04 上打的，
> **glibc 上限就是打包机那一版**，换更老的系统需要在更老的机器上重新打包。

### 串口权限（首次必做）

```bash
sudo usermod -aG dialout $USER
```

**执行后必须注销重新登录**（或重启）才生效。不做这一步的表现是：能打开界面，但端口列表是空的 / 连不上。

---

## 三、连接机械臂

1. 用 USB 线把机械臂控制板接到电脑。
2. 界面左上角选择端口（板子通常枚举成 `/dev/ttyACM0`；若机器上同时插了调试探针，可能是 `ttyACM1`）。
3. 点 **[连接]**。

> 端口号会随插拔顺序变化。分不清哪个是板子时：拔掉板子刷新一次端口列表，消失的那个就是。

---

## 四、配置文件

`config.yaml` 就在可执行文件旁边，**可以直接用文本编辑器改**（例如默认端口、界面参数）。

查找顺序（前面存在就用前面那个）：

1. 环境变量 `LITEARM_TOOL_CONFIG` 指定的路径
2. **当前工作目录**下的 `config.yaml`
3. **本目录**（可执行文件旁边）的 `config.yaml`
4. 包内自带的一份基线

改动后重启程序生效。

## 六、常见问题

**界面起不来 / 一闪而过**
从终端启动一次，把打印出来的错误发给我们。常见原因是 glibc 版本不够（见第二节）。

**端口列表是空的**
十有八九是 `dialout` 组没生效（见第二节）。确认后仍为空，检查 USB 线是否是数据线（有些线只能充电）。

**连上了但状态一直是"离线"**
说明没有收到状态帧：确认机械臂已上电、USB 线接的是**控制板**而不是别的设备、
以及没有另一个程序占着同一个串口（同一个口不能两个程序同时打开）。

**改安装方向 / 写参数被拒绝，提示"须先失能"**
这是**安全设计**，不是故障。改安装方向会让重力补偿瞬间跳变，必须先到 **[整机]** 页点
[失能 disable]，再回参数页操作。

**要恢复出厂设置**
到 **[参数表]** 页点 [恢复出厂]（同样须先失能）。注意这会清掉这台机器已标定的动力学参数。

## 七、固件升级（USB DFU）

界面「参数 → 固件升级」可以通过 STM32 ROM bootloader（`0483:DF11`）烧录 `.hex` / `.bin`
固件。包内已经带好 pyusb + libusb，**目标机不需要另装**。

Linux 首次使用需要一条 udev 规则（否则 DFU 设备会报"权限不足"）：

```bash
echo 'SUBSYSTEM=="usb", ATTR{idVendor}=="0483", ATTR{idProduct}=="df11", MODE="0666"' \
  | sudo tee /etc/udev/rules.d/49-litearm-dfu.rules
sudo udevadm control --reload-rules && sudo udevadm trigger
```

Windows 上还需要给 DFU 设备安装 ST 的 WinUSB 驱动。

> ⚠ 升级会先让机械臂**失能**（有重力负载会下垂，先放稳/支撑）；升级期间软件急停无效，
> 只能靠硬件急停/断电。许可证与出厂标定所在的扇区不会被触碰。

## 八、日志 / 反馈问题

界面右下角有日志面板，出错信息会带 `[ERR]` 前缀显示在那里。

反馈问题时请一并提供：

- 报错原文（或日志面板里的 `[ERR]` 行）
- 界面左上角显示的**固件版本**
- 机械臂型号与连接方式
